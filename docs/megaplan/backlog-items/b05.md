# b05: Reusable ICM starter workspace

## Outcome

A replicator can copy starter/ into any project and get a working hybrid-ICM workflow: root CONTEXT.md routing, numbered stage contracts (Inputs/Process/Outputs + checkpoints), an onboarding questionnaire, and a pointer to this repo as the worked example. Operator confirms by walking the starter's files against the conventions.

- [x] Starter shape agreed with operator

## Touches

- starter/ (new directory; contents per design)
- README.md (one row/line pointing at starter/, if design lands it there)
- CONTEXT.md routing table (one row, same condition)

## Not touching

- The repo's own stages/, docs/megaplan/, policies (they are the worked example, not the template)
- Agent definitions, installers (done items)
- Validation matrix (b06)
- Origin remote; nothing committed or pushed without operator authorization

## Cut

No live instance inside the repo — the starter is template files users copy out; the repo's own structure (b02) is the live proof. No tooling/scripts; markdown only. No macOS/WSL validation (b06).
