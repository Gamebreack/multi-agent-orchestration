# b04: Harness-explicit, backup-aware installation and safe uninstall

## Outcome

Each harness's orchestration layer installs with one command (./install.sh claude|opencode|antigravity) and uninstalls safely (./uninstall.sh <harness>): install is backup-then-copy of that harness's files only; uninstall removes only files still byte-identical to the repo's (user-edited files are skipped with a warning; --purge overrides). Config wiring, personal opencode.jsonc and personal MCP allow rules stay manual (documented). Operator confirms via one sandbox install/uninstall/reinstall cycle.

## Scope

- [x] Simplified design agreed with operator (KISS: no manifests, no restore logic, no merge engine, no harvest automation)
- [x] install.sh + uninstall.sh rewritten as single cross-harness scripts (harness argument)
- [x] Repository docs reviewed for consistency with the new interface (README, docs/opencode.md, docs/antigravity.md, CONTEXT.md, megaplan.md negatives)
- [x] Sandbox install/uninstall/reinstall cycle verified
- [x] Operator approval checkpoint passed

## Touches

- install.sh, uninstall.sh (full rewrite: harness argument, backup-then-copy, match-check removal)
- README.md (quick start), docs/opencode.md and docs/antigravity.md (install sections), CONTEXT.md (routing row)
- docs/megaplan/megaplan.md (negatives: "no OpenCode installer" becomes false)

## Not touching

- Agent definitions' content (the installer copies files; it never edits them)
- Any config file content except the Claude settings.json hook entry: never mcp.servers entries, quota plugin, provider auth, unrelated agents, or the Antigravity plugin-enable key
- The starter workspace (b05), validation matrix (b06)
- Origin remote; nothing committed or pushed without operator authorization

## Cut

No manifest files, no backup-restore on uninstall, no config merging, no MCP-rule harvesting — the orchestrator template's comment and docs/opencode.md already tell the operator to add personal MCP allow rules. No live execution against the operator's real environment; verification uses env-overridden config dirs (sandbox). No macOS/WSL validation (b06).
