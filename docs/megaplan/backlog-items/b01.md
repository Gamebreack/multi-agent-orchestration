# b01: ICM architecture checkpoint

## Outcome

Operator decides the ICM architecture (single-agent canonical ICM vs ICM+specialists hybrid) with
evidence from a written comparison and an optional small pilot; no migration before the decision.

Comparison summary:

- **Single-agent canonical ICM** — one agent walks numbered stage folders, `CONTEXT.md` contracts
  (Inputs/Process/Outputs), plain-text handoffs, operator checkpoints. Simplest and most portable;
  but the repo's hard safeguards (read-only orchestrator enforcement, fresh-context independent
  review/verification, per-role model tiering) become prompt-level policy only.
- **ICM+specialists hybrid** — ICM stages/contracts organize work and context; the orchestrator
  delegates stage work to existing specialist agents. Preserves enforcement and tiering; costs more
  moving parts and per-harness adapters; is an adaptation of ICM, not the canonical form.
- **Pilot (executed 2026-09-25)** — one small agent-policy fixture change run both ways; measure
  files touched, context loaded, integrity of the review/verification gate, operator effort.
